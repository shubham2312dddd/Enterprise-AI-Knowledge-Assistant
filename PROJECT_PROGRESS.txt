ENTERPRISE AI KNOWLEDGE ASSISTANT
PROJECT PROGRESS
Last updated: 2026-11-13

PROJECT GOAL
Build a React and FastAPI application that lets users upload PDFs, index their
contents locally, and retrieve relevant source passages from one or more
documents. Retrieval and local LLM answer generation are implemented.


COMPLETED MILESTONES

1. React frontend and FastAPI PDF upload
   - Built a Vite/React dashboard with application branding, navigation,
     responsive layout, PDF upload, drag-and-drop, and browse-file support.
   - Added upload status, filename and file size display, errors, extracted
     text preview, and backend health/connection status.
   - Added FastAPI CORS support for http://localhost:5173.
   - Preserved GET / and GET /health.
   - Added PDF upload validation, including a 20 MB limit, empty/invalid PDF
     handling, and page-by-page text extraction with PyMuPDF.
   - The chat area was initially a visual placeholder and was enabled in
     Milestone 3 after retrieval was verified.

2. PDF ingestion and retrieval pipeline
   - Added page-aware PDF extraction, preserving original page numbers and
     recording empty pages, page count, and extracted character count.
   - Added reusable chunking with approximately 800 characters per chunk and
     150 characters of overlap. Chunks retain source page information.
   - Added local Ollama embeddings using the nomic-embed-text model and its
     /api/embed endpoint. Embedding requests are validated and use timeouts.
   - Added persistent ChromaDB storage under backend/vector_db/.
   - Indexed document chunks with unique document IDs and source metadata.
   - Added similarity search returning source text, filename, page number, and
     cosine distance. Lower cosine distance indicates a closer match.

3. Retrieval diagnosis and multiple-document support
   - Traced search queries from the React input through Axios, FastAPI,
     Ollama, ChromaDB, and back to the results UI.
   - Confirmed the search sends the latest question, creates a fresh query
     embedding for each request, and replaces old results. No fixed questions,
     cached query vectors, or hardcoded retrieval answers were found.
   - Diagnosed the primary retrieval issue: Nomic task prefixes were missing.
     Document chunks now use "search_document:" and user queries use
     "search_query:".
   - Migrated the existing stored vectors in place using their existing text.
     Document IDs, chunk IDs, text, and metadata were preserved. The migration
     is idempotent and does not require re-extracting or rechunking PDFs.
   - Added a persistent document list, all-document or selected-document
     search, and isolated deletion of an individual document.
   - Search results show actual retrieved passage text with its PDF filename
     and original page. No page-specific logic or prewritten answers are used.

4. RAG-based LLM question answering
   - Added a local Ollama chat service using OLLAMA_CHAT_MODEL and
     OLLAMA_CHAT_TIMEOUT environment variables. The default answer model is
     qwen2.5:1.5b-instruct.
   - Added a RAG service that reuses the Nomic query embedder and existing
     document-filtered ChromaDB search, then sends bounded retrieved text to
     the local model.
   - Added a strict prompt that treats PDF passages as untrusted evidence,
     forbids unsupported claims and fabricated citations, and instructs the
     model to abstain when context is insufficient.
   - Added a configurable cosine-distance guard. With the default threshold
     of 0.48, no sufficiently close passage returns an insufficient-information
     response without calling the LLM.
   - Added POST /api/chat with optional document IDs, top_k validation,
     model/embedding/database error handling, and source references derived
     from actual ChromaDB metadata.
   - Enabled the React chat input, document-scope selector, multi-question
     session, loading/error states, duplicate-submit protection, and expandable
     filename/page/excerpt references.
   - Preserved the existing /api/search response shape and the existing PDF,
     embedding, ChromaDB, and multi-document workflows.

5. Qwen model and retrieval tuning
   - Switched the centralized OLLAMA_CHAT_MODEL default to
     qwen2.5:1.5b-instruct. No model was downloaded.
   - Kept document and query embedding configuration unchanged. Ollama
     resolves the configured nomic-embed-text model to nomic-embed-text:latest.
   - Set default top_k to 3 across chat, retrieval endpoints, the RAG service,
     and frontend API helpers. The supported range remains 1 through 20.
   - Calibrated the default cosine-distance relevance cutoff from 0.4 to 0.48
     after a relevant GreenLeaf results passage at distance 0.463 was rejected
     by the previous cutoff. Similarity scores and ranking are unchanged.


CURRENT API
- GET /                         Health-style home response
- GET /health                   Backend health check
- POST /api/documents/upload    Upload, extract, embed, and index a PDF
- GET /api/documents            List indexed documents
- DELETE /api/documents/{id}    Delete only the selected document's chunks
- POST /api/search              Search all documents or selected document IDs
- POST /api/chat                Generate a grounded answer with actual sources
- POST /api/documents/{id}/search
                                Search one specific document
- GET /docs                     FastAPI Swagger documentation

Search requests accept a non-empty query and top_k from 1 to 20; top_k defaults
to 3. The general search endpoint searches all documents when document_ids is
omitted; when IDs are provided, results are filtered to those documents.


IMPLEMENTATION AREAS
- backend/main.py: FastAPI routes, request validation, CORS, upload and search.
- backend/services/pdf_processor.py: page-by-page PDF extraction and statistics.
- backend/services/text_chunker.py: page-aware text chunks and overlap.
- backend/services/embedding_service.py: Ollama embedding requests and
  Nomic task prefixes.
- backend/services/llm_service.py: configurable local Ollama chat requests,
  low-temperature generation, response validation, and safe errors.
- backend/services/rag_service.py: retrieval/context orchestration, context
  size and distance guards, prompt-injection handling, and source references.
- backend/services/document_indexer.py: coordinates chunking, embeddings, and
  storage.
- backend/services/vector_store.py: persistent ChromaDB, metadata, filtering,
  search, document listing, and deletion.
- backend/services/embedding_migration.py: safe, repeatable migration of
  existing vectors to the current embedding profile.
- frontend/src/components/: reusable upload, search, chat, header, and
  navigation UI components.
- frontend/src/components/ChatWindow.jsx and ChatInput.jsx: multi-question
  chat session, document selection, loading, errors, and source display.
- frontend/src/services/api.js: frontend API calls.
- README.md: setup instructions and API documentation.
- PROJECT_PROGRESS.txt: project milestones and verification history.

HOW TO RUN
Prerequisites: the existing Python virtual environment, Node.js/npm, and
Ollama running locally with nomic-embed-text:latest and
qwen2.5:1.5b-instruct available.

Backend (from the project root, in PowerShell):
  .\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000

Optional backend environment overrides (set before starting Uvicorn):
  $env:OLLAMA_CHAT_MODEL = "qwen2.5:1.5b-instruct"
  $env:OLLAMA_CHAT_TIMEOUT = "120"
  $env:RAG_MAX_COSINE_DISTANCE = "0.48"

Frontend (in another PowerShell window):
  Set-Location .\frontend
  npm install
  if (-not (Test-Path .env)) { Copy-Item .env.example .env }
  npm run dev

URLs:
  Frontend:  http://localhost:5173
  Backend:   http://127.0.0.1:8000
  API docs:  http://127.0.0.1:8000/docs
  Ollama:    http://localhost:11434

Backend unit tests (from the project root):
  .\.venv\Scripts\python.exe -m unittest discover -s backend\tests -v

Frontend checks (from frontend/):
  npm run lint
  npm run build

The existing Chroma database is already migrated. If setting up an older
database created before the Nomic prefixes were added, run this once from the
project root:
  .\.venv\Scripts\python.exe -m backend.services.embedding_migration
